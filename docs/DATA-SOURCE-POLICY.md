# Agent Radar Data Source Policy

Effective date: September 17, 2026

## Priority

1. Official release pages, official documentation, official announcements, and official repository commits.
2. GitHub repository metadata and GitHub Trending as discovery signals.
3. Community discussions only as context, never as proof of an official release or requirement.

## Original summaries

Agent Radar writes short original explanations and links back to the source. It must not republish a complete README, article, documentation page, source file, or paywalled content. Quotations must be short, necessary, clearly attributed, and within the source's applicable terms.

## Evidence labels

Each Agent update and GitHub item must include:

- `source_type`;
- original `source_url` or repository `url`;
- `source_checked_at`;
- `source_check_status`;
- `ai_assisted`;
- `human_reviewed`.

`source_check_status: api_verified` means only that the repository, release, or commit endpoint existed when checked. It does not prove every summary sentence. `human_reviewed: true` may only be used after a person checks the original source against the published summary.

## GitHub Trending

Trending is a point-in-time popularity signal. Do not describe a Trending appearance as a release, security review, recommendation, or quality certification. Preserve source order and do not invent missing entries.

## Corrections

If a source is removed, changes materially, conflicts with another official source, or a summary is wrong, mark the item, correct it, and record the correction date. Do not silently convert an unverified statement into a verified fact.
